Executive Summary

ALIAS (Autonomous Lifecycle Intelligence & Advertising System, also referenced in early design stages as CampaignMind) is an autonomous marketing agency application engineered to eliminate the manual, sluggish, and fragmented workflows of traditional digital agencies. Instead of 30-field intake questionnaires, multi-week onboarding delays, and subjective PowerPoint presentations, ALIAS provides an intelligent conversational intake interface, an automated competitor and market research engine grounded in real web data, and an administrative communication control hub with automated, safety-filtered client dispatch.

Throughout the engineering lifecycle of ALIAS Part 1, the developer adopted an advanced Tri-Agent Collaborative Model. Rather than treating AI as a simplistic code-completion tool, AI was systematically partitioned into specialized roles:

  • ChatGPT (The Conceptual Architect & UX Designer): Spearheaded early ideation, reverse-engineered enterprise marketing platforms from live URLs, authored realistic bilingual (Bengali-English) client dialogues, designed JSON schemas, and audited external API integrations.
  • Claude (The Senior Engineering Strategist & Forensic Critic): Functioned as an architectural review board. Claude analyzed live server log traces, resolved thorny infrastructure and Windows network bugs (such as MongoDB DNS SRV failures), evaluated Antigravity's proposals critically, and enforced strict security and secret rotation policies.
  • Google Antigravity (The Autonomous Coding Agent): The hands-on builder inside the IDE workspace. Antigravity synthesized full-stack Next.js 16 App Router code, implemented responsive React 19 interfaces, orchestrated atomic MongoDB outbox workers, engineered Tavily web crawlers, and executed 95 automated Vitest unit and integration tests.

1. Strategic Product Ideation & Competitive Reverse-Engineering

1.1 Deconstructing Enterprise Competitors (AIPraktor)

The project began with a competitive analysis of commercial autonomous marketing software. The developer supplied the live URL https://www.aipraktor.com/ to ChatGPT with explicit instructions: dissect the underlying system architecture, data pipelines, and agentic workflows rather than summarizing surface-level landing page marketing copy.

Through prompt exchanges conducted in Bengali ("ayta nia deatils a bolo in bangla"), ChatGPT unpacked how commercial AI marketing platforms coordinate autonomous sub-agents: extracting campaign goals from clients, gathering market intelligence via search APIs, and outputting actionable creative strategies. This established the clear technological differentiation between a conventional marketing agency and ALIAS:

Dimension Traditional Marketing Agency ALIAS Autonomous Platform
Client Onboarding 3–5 manual discovery meetings, static 30-field questionnaires, 7–14 days turnaround time. Conversational AI consultant (AG-1) extracting structured parameters into a live dossier in <15 mins.
Market Research Subjective manual Google searching, unverified slide decks, static competitor quotes. Automated Tavily search with live HTTP 200 status, SSL verification, and evidence grounding.
Deliverable Format Generic strategy PDFs requiring third-party agencies for copy and media buying. Structured 3-Artifact pipeline: Reactive Dossier, Verified Research, and Phone-Camera-Ready Execution Scripts.

1.2 The Three-Artifact Architecture

Working collaboratively with AI, the project deliverables were structured into three modular, loosely coupled data artifacts:

  • Artifact 1 (Client Campaign Brief / Reactive Dossier): Dynamically synthesized during natural conversation. Captures business category, product USPs, target demographics, geographical focus, and budget constraints without forcing clients to complete rigid forms.
  • Artifact 2 (Verified Competitor & Market Research): Autonomous web research gathered via Tavily API and filtered through live HTTP and DNS validation checks to prevent LLM hallucinations.
  • Artifact 3 (Master Campaign Brief & Execution Script): Operational, camera-ready creative scripts and localized media plans (e.g., Bangladesh Cash-on-Delivery, Pathao/Steadfast courier logistics, Meta Ads targeting).
Architectural Constraint: Separating Facts from Speculation
In ChatGPT's schema design, the user mandated strict separation between client_stated attributes and research_insights. If an agency client explicitly states their product price is 1,200 BDT, AI must never overwrite it with external market estimates.

2. Conversational UX & Non-Interrogative Entity Extraction

2.1 Eradicating Survey Fatigue

A universal failure mode of automated onboarding chatbots is "interrogative survey fatigue": subjecting the user to 20 consecutive single-attribute questions. The developer instructed AI to design an organic, conversational consulting flow:

User Prompt (Bengali): "chat er moddah example dia buja conversetion ta ki hoba kmn" (Explain with a concrete example of how the client intake conversation will naturally flow).

In response, ChatGPT authored a complete simulation between an AI Consultant (AG-1) and an apparel merchant launching premium men's formal shirts in Bangladesh. The interaction demonstrated two vital prompt engineering rules:

  • Multi-Attribute Compound Inference: When the client volunteers "We sell luxury formal shirts for young corporate professionals in Dhaka with a launch budget of 50,000 BDT", the extraction engine simultaneously extracts four distinct entities: industry: "apparel", product: "formal shirts", location: "Dhaka, Bangladesh", and budget: 50000.
  • The Non-Redundancy Guarantee: The AI Consultant tracks all extracted entities in an active memory state and never asks for information that has already been provided.
  • Explicit Uncertainty Handling: If an attribute (such as target customer age range) remains unstated, the system records it as [UNKNOWN - Pending Clarification] rather than guessing or hallucinating default values.

2.2 The Human-in-the-Loop State Machine

The user formulated the operational boundary between client onboarding, administrative oversight, and background research:

User Prompt: "ami bolta chaici je conversation er por acta artifact generate korba... tarpor ayta mr next part re diba" (I want the system to generate an artifact after the conversation finishes, and then pass it to the next stage).

AI translated this requirement into a rigorous 4-step state machine:

  1. Client Intake Phase: Natural language dialogue extracts facts into a mutable draft of Artifact 1.
  2. Synthesis & Versioning: The conversation locks, producing an immutable Artifact 1 snapshot (v1).
  3. Administrative Confirmation: Agency account directors review, edit, and approve the dossier in the Admin Dashboard (upgrading to v2/v3).
  4. Research Engine Handoff: Only after formal admin approval does the system trigger the automated Tavily research worker to synthesize Artifact 2. The research engine consumes the confirmed artifact directly, never reading raw unparsed chat logs.

3. Infrastructure Engineering & The MongoDB DNS War

3.1 The Network SRV Blocker (querySrv ECONNREFUSED)

During the transition from an in-memory test store to a production MongoDB Atlas cluster, the application encountered a catastrophic connection failure. Running scripts/test-db.ts produced the following terminal error:

Database Test FAILED with error: Name: Error Message: querySrv ECONNREFUSED _mongodb._tcp.cluster0.l8o9l5m.mongodb.net Code: ECONNREFUSED

3.2 The Multi-AI Debate: Antigravity vs. Claude

This incident showcased the unique value of pitting an autonomous coding agent against a senior reasoning model:

  • Antigravity's Proposed Fix: Antigravity observed that calling dns.setServers(['8.8.8.8', '1.1.1.1']) inside Node.js bypassed the local Windows network DNS blocker and allowed mongoose.connect to succeed. It proposed embedding this DNS patch directly into application startup code.
  • Claude's Architectural Intervention: When the developer presented this diagnostic output to Claude in Bengali, Claude immediately objected:
    Claude's Architectural Ruling
    "Antigravity dns.setServers কোডে বসাতে বলেছিল। সেটা কাজ করবে, কিন্তু প্রোডাকশনে ঢুকে যাবে, আর যেকোনো নেটওয়ার্কে (অফিস, ক্লায়েন্ট) অপ্রয়োজনে বাইরের DNS জোর করবে। কোডে DNS হ্যাক বসাবেন না।"
    (Antigravity wanted to inject dns.setServers into the code. While it works locally, it forces external DNS on corporate/client networks and pollutes production. Do not put DNS hacks in application code.)
  • The Production-Grade Resolution: Claude guided the developer to MongoDB Atlas's driver configuration page to activate the "Legacy URI String" toggle. This generated a standard non-SRV connection string explicitly naming the three replica set shard hosts (shard-00-00, shard-00-01, shard-00-02).

By updating .env.local with the non-SRV URI, Node.js avoided DNS SRV lookups entirely. The application connected cleanly, completed multi-document ACID transactions, and successfully switched from RAM fallback to true MongoDB persistence without a single line of fragile DNS monkey-patching.

4. Full-Stack Implementation via Autonomous Coding Agents (Antigravity)

With architecture and infrastructure resolved, the developer directed Antigravity to build the full-stack Next.js 16.3 and React 19 application:

4.1 The 3-Panel Admin Communication Hub (/admin/communication)

Antigravity constructed a unified agency control center designed for high-velocity account management:

  • Panel 1 (Client Thread Directory): Displays active client campaigns with live unread notification badges, search filtering, and real-time MongoDB sync.
  • Panel 2 (Multi-Party Conversation Stream): Real-time transcript renderer that clearly distinguishes between messages from the Client, the Agency Admin, and ALIAS AI (Auto-Reply Engine), complete with status tags (draft, approved, dispatched).
  • Panel 3 (AI Communication Copilot): Analyzes the recent client transcript and generates 3 distinct suggested responses:
    • Professional: Formal, structured, and milestone-focused.
    • Friendly: Warm, relationship-building, and approachable.
    • Detailed: In-depth breakdown with operational timelines and next steps.
  • 10-Second Auto-Dispatch Countdown: Features an animated visual progress bar giving human administrators a 10-second window to pause, edit, or reject automated AI responses before outbound delivery.

4.2 Durable MongoDB Outbox Worker & Concurrency Fencing

To prevent message drops and duplicate dispatches during high traffic, Antigravity implemented a durable outbox pattern:

  • Token-Based Atomic Locking: Workers claim pending messages using MongoDB findOneAndUpdate with atomic version fencing, preventing race conditions across serverless instances.
  • Stale Worker Recovery: Background heartbeat loops detect orphaned jobs from crashed processes and re-queue them safely after a 60-second lease expiry.
  • ACID Multi-Document Transactions: Dispatched messages and audit log entries update atomically inside a replica set transaction, guaranteeing zero partial writes.

5. Forensic Root-Cause Debugging & Log Auditing

A standout characteristic of this project was the developer's use of AI for cross-tool diagnostic auditing. Rather than guessing at bugs, raw terminal stack traces, server logs, and database records were fed into Claude and ChatGPT:

5.1 Bug 1: The Duplicate Auto-Reply Storm

  • Symptom: In client intake chats (/campaign/[id]), every user prompt received two bot responses: one from the interactive onboarding bot and a duplicate from the background auto-reply worker.
  • Forensic Diagnosis: AI analyzed the polling worker logic and found that the query { status: 'pending' } was matching all threads indiscriminately.
  • Fix: Enforced strict thread isolation: threads with type: 'intake' were excluded from the auto-reply dispatch queue, leaving onboarding strictly to the dedicated intake agent.

5.2 Bug 2: Semantic Parser Collision (Audience Age vs. Duration)

  • Symptom: When a user typed "Audience age 18-30 year", the intake entity extractor mistakenly updated the campaign duration to "18-30 years".
  • Forensic Diagnosis: The entity regex matched any digit followed by "year/month/week" without semantic context checks.
  • Fix: Introduced semantic disambiguation guards requiring explicit duration keywords ("campaign length", "running for", "duration") before touching campaign timeline fields.

5.3 Bug 3: Port 3000 Zombie Server Collision

  • Symptom: During server restarts, Next.js threw EADDRINUSE: address already in use :::3000.
  • Forensic Diagnosis: Claude identified an orphaned Node.js process (PID 796) running in the background that had failed to terminate after a terminal crash.
  • Fix: Executed Stop-Process -Id 796 -Force in PowerShell to release the socket cleanly.

5.4 Bug 4: Google Gemini 503 UNAVAILABLE & Rate Limiting

  • Symptom: UI displayed a red alert box: "Failed to process chat message".
  • Forensic Diagnosis: Antigravity extracted the exact server log: Google Generative AI returned 503 Service Unavailable (transient upstream overload) and occasional 429 Resource Exhausted rate limits.
  • Fix: Implemented a 5-minute circuit breaker cooldown paired with a local deterministic rule fallback engine. Crucially, the system tags fallbacks transparently with provider: "fallback" so operators know whether a suggestion originated from Gemini or local rules.

6. Anti-Hallucination Engineering & Evidence Grounding

6.1 The Urban Style Research Audit

Generative AI tools frequently invent competitor statistics and cite broken links. To eliminate hallucinations, the developer integrated the Tavily Web Search API and conducted a forensic audit (audit-urban-research-quality.ts) using a real-world test brand ("Urban Style").

The audit revealed a profound engineering insight: an HTTP 200 status code is not proof of factual verification! Out of 15 sources marked as "verified":

  • One URL pointed to a store-locator page that had no competitor pricing data.
  • Another URL matched an unrelated fleet-management software company due to a brand name collision.
  • A third URL cited a YouTube video player disclaimer rather than substantive marketing analysis.

6.2 Hardening the Evidence Crawler (url-validator.ts)

ChatGPT and Antigravity completely redesigned the evidence verification pipeline to enforce fail-closed validation:

  • Deep Content Verification: The validator requires substantive brand mentions and extracted keyword proximity in the fetched DOM before accepting a URL.
  • DNS & SSL Handshake Checks: Verifies TLS certificate validity and flags parked or expiring domains.
  • Deterministic Domain Pinning: Competitor official domains are explicitly pinned; generic third-party aggregator links are suppressed.

7. Security Protocols & Credential Hygiene

During interactive debugging, a diagnostic screenshot of the IDE accidentally captured an open .env.local file displaying active MongoDB Atlas passwords and Gemini API keys.

Security Alert Flagged by Claude
"আগে একটা জরুরি জিনিস: এই স্কিনশটে .env.local পুরো খোলা ছিল। আপনার MongoDB পাসওয়ার্ড আর Gemini API key দুটোই পড়া যাচ্ছে, এখন এই চ্যাটে আছে। অবিলম্বে পাসওয়ার্ড বদলান এবং নতুন API key নিন।"
(Immediate warning: .env.local was fully visible in this screenshot. Your MongoDB password and Gemini API key were exposed. Change your database password and rotate the API key immediately.)

The developer immediately executed an emergency security protocol guided by AI:

  1. Rotated the MongoDB Atlas database user password in Atlas Access Control.
  2. Revoked the compromised Gemini API key in Google AI Studio and provisioned a fresh secret.
  3. Updated local .env.local files and verified that git tracking ignored all environment files.
  4. Established a permanent development rule: Never share raw credentials or unfiltered IDE screenshots in AI chats.

8.2 Core Methodological Lessons

  1. A Passing Status is Not Proof: 95 passing tests or an HTTP 200 status code do not guarantee factual accuracy. Real-world validation against live business data is non-negotiable.
  2. Constrained Prompts Beat Open-Ended Requests: Prompts that explicitly listed negative constraints ("do not redesign", "do not inject DNS hacks", "do not replace Tavily") produced far superior code than vague requests.
  3. Tri-Agent Collaboration Maximizes Quality: Separating high-level strategy (ChatGPT), critical code review (Claude), and hands-on synthesis (Antigravity) created an exceptional balance of development speed, architectural stability, and security.
